RELEASE_CHECKLIST.md¶

zomi‑syl v0.2.0 — Hybrid Release Checklist (Manual → CI)¶

A strict release checklist for preparing and publishing zomi‑syl v0.2.0.
All manual steps must be completed before CI is allowed to run.

A. Manual Steps (must be done before CI)¶

A1. Versioning¶

  • Update version in pyproject.toml:
version = "0.2.0"
  • Add v0.2.0 entry to CHANGELOG.md
  • Confirm CLI reports correct version:
python -m zomi_syl version

A2. Model Directory Structure¶

Required layout:

src/zomi_syl/models/
  crf/
    config.json
    crf_syllabifier.joblib
  rule/
    ruleset.json
    metadata.json

Checklist: - [x] No models under ./src/models/bundled/
- [x] Loader does not reference bundled/
- [x] Registry resolves models/<model-name>/ correctly
- [x] storage.local_path in metadata is ""

A3. Packaging: Include All Required Files¶

Ensure pyproject.toml includes:

[tool.setuptools.package-data]
zomi_syl = ["models/**/*", "profiles/**/*", "config/*.toml"]

Verify: - [x] CRF model files included
- [x] Rule model files included
- [x] Profiles included
- [x] Config files included

Local test:

python -m build
pip install dist/zomi_syl-0.2.0-py3-none-any.whl
python -m zomi_syl syllabify "themthum"

A4. CLI Validation¶

Run:

python -m zomi_syl version
python -m zomi_syl syllabify "themthum"
python -m zomi_syl syllabify --backend rule "kiginna"
python -m zomi_syl syllabify --backend crf "kiginna"

Confirm: - [x] No stack traces
- [x] No missing model errors
- [x] No fallback to bundled paths
- [x] Rule + CRF backends load correctly

A5. Profiles Validation¶

Run:

python -m zomi_syl profiles validate tedim
python -m zomi_syl profiles validate paite

Confirm: - [x] Profiles load
- [x] No missing keys
- [x] Validators pass

A6. Documentation¶

  • README includes installation, quickstart, backend usage, examples, supported profiles, HF model links
  • Validate PyPI rendering:
twine check dist/*

A7. Code Cleanup¶

  • Remove development artifacts
  • Remove unused files
  • Ensure no temporary or experimental code remains

A8. Makefile Developer Help Targets¶

Check:

make help-devs
make help-cli
# Todo:
# make help-backends
# make help-models

A9. Licensing¶

  • LICENSE file present
  • Model/data licenses compatible
  • HF repos referenced properly

A10. Final Manual Sanity Check¶

Install from wheel:

pip uninstall -y zomi_syl
pip install dist/zomi_syl-0.2.0-py3-none-any.whl
python -m zomi_syl syllabify "themthum"

Verify: - [x] CLI works
- [x] CRF backend loads
- [x] Rule backend loads
- [x] No missing files
- [x] No warnings

B. CI‑Driven Steps (automated)¶

B1. CI Build Pipeline¶

  • CI builds wheel + sdist in a clean environment
  • No leftover artifacts (dist/, build/, .egg-info/)
  • Package‑data rules include all required assets
  • Version in pyproject.toml matches the release tag

B2. CI Test Pipeline¶

  • All tests pass
  • CRF consistency tests pass
  • CRF regression tests pass
  • No unexpected failures
  • No warnings or deprecations flagged

B3. CI Lint & Type‑Check Pipeline¶

  • Linting passes
  • Formatting passes
  • Type checks pass

B4. CI Documentation Pipeline¶

  • README renders correctly
  • Documentation builds (if applicable)
  • No broken links or missing assets

B5. CI Publish Pipeline¶

Triggered only on tagged releases.

  • PyPI credentials stored in CI secrets
  • CI uploads artifacts to PyPI
  • Upload succeeds
  • PyPI page updates with new version
